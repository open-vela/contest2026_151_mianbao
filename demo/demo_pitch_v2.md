# 预面演示话术 v2（覆盖框架外追问）

> 基于 20 场实测：每条线 5 场技术向 + 5 场产品/失败/团队向，共收集约 100 条追问。
> **数字是示例，换成你实际能解释口径的数**；解释不了的数字不要报。
> 旧版：[demo_pitch.md](demo_pitch.md)（5 轮主线，仍可参考）。

## 0. 面试官真正在追的 6 条主线

不管问法怎么变，几乎都落在这六类。每答一条，尽量带一个具体例子或数字。

| 主线 | 典型问法 | 答题公式 |
|---|---|---|
| **你个人做了什么** | 你负责哪一块？团队几个人？谁定的标准？ | 我负责 X → 交付物是 Y → 指标是 Z；团队另外两人做 A/B |
| **数字的口径** | 65% 在什么数据上测的？50 条怎么选？算过 recall 吗？置信区间？ | 样本量 + 抽样方式 + 分布 + 只代表方向，不吹成结论 |
| **失败与恢复** | 某一步挂了怎么办？格式不对/超时怎么处理？会重试还是降级？ | 分层重试 → 降级 → 标记不确定 → 人工兜底 |
| **规则还是模型/工具** | 这是规则还是模型判断？为什么不用端到端？ | 规则负责召回/计数，模型负责抽取/判断，工具负责可验证的事 |
| **评测与回归** | 改完怎么证明变好了？测试集怎么建？换一批还能复现吗？ | 固定回归集 + 分层抽样 + 指标（precision/recall/一致性） |
| **业务与边界** | 谁用？值不值得做？版权/隐私？下一步？ | 先给场景和用户，再说边界和下一步，不空谈商业化 |

> 面试官经常“跳出去”，不是跑题：他是在验证你是不是只会讲 pipeline。
> 被问到没准备的，用「结论 → 一个具体例子 → 边界/下一步」三段式，不要沉默。

## 1. 线 A：智能体开发 × 灵感发现智能体

### 1.1 30 秒项目介绍（第一次 K1 说）

> 我是做 AI 应用和智能体的。最近做了一个「灵感发现」智能体：从社区和视频评论区里
> 找那些**现在还没有、但有人在反复问**的需求。它先用固定提示词把相关评论筛出来，
> 再抽取需求、人群、场景和现有替代方案，最后打分输出候选清单。我负责整体编排、
> 提示词和评测。

### 1.2 问题地图（实测问法 + 回答要点）

#### ① 个人贡献 / 团队

- “你负责哪一块？团队几个人？”
- “三条标准是谁定的？模型还是你们？”

**答**：我负责 agent 编排、提示词和评测；一个工程做采集和平台适配，一个产品做人工验证。
标准我先起草，产品拍板，每周 bad case 会一起改。**不要说“我们团队”就结束，要落到自己。**

#### ② 固定提示词 / 需求判断

- “怎么判断一条评论是固定提示词而不是真实需求？准确率多少？”
- “固定提示词是规则还是模型识别？举个例子。”

**答**：固定提示词只是**召回**；召回后用模型抽三要素：人群、场景、现有替代方案。
三要素缺一个就降级，不直接进候选池。抽检 50 条 precision 约 65%，误判主要是反讽和广告。

#### ③ 指标口径（最容易被追穿）

- “65% 在什么数据上测的？50 条怎么选？算过 recall 吗？置信区间？”
- “人工标注标准谁定的？几个人标？一致性多少？”

**答**：50 条是按来源分层抽的，不是随机；只代表方向，置信区间很宽。
recall 还没系统算，下一步扩到每周 100~200 条，加 Kappa 看标注一致性。
**先承认样本小，再给改进计划**——比硬说“很准”可信。

#### ④ 去重 / 聚类

- “两条评论措辞和场景差别很大，怎么判断是同一个需求？模型还是规则？”

**答**：两层：embedding 相似度先粗聚，再用需求要素（人群/场景/动作）对齐；
边界 case 进人工抽检。模型做语义，规则做阈值和去重计数。

#### ⑤ 验证 / 替代方案 / 伪需求

- “三条验证规则，单一平台强烈需求丢不丢？”
- “有没有替代方案怎么判断？靠检索还是模型？误判怎么兜底？”

**答**：单一来源的强烈需求不直接丢，进“观察池”；至少两个独立来源才进候选。
替代方案优先用搜索/产品库检索，模型只做归纳；判断错就降级为“待人工确认”。

#### ⑥ 架构 / 工具 / 失败恢复

- “串行 pipeline 还是 agent 自主规划？某一步失败怎么恢复？格式不对/超时呢？”

**答**：串行 pipeline + agent 编排；模型只做抽取和判断，抓取/计数/去重交给工具。
每步可单独重试；重试两次仍失败就降级为“部分结果 + 标记不确定”，不阻塞整条链路。

#### ⑦ Prompt 迭代 / 回归

- “negative examples 怎么构造？规则还是 prompt？改完怎么确认比旧版好？”
- “反讽误判又冒出来，怎么定位是提示词、上游过滤还是打分？”

**答**：bad case 分两类：边界/格式 → 改 system prompt 规则；长尾表达 → 进 few-shot。
用固定 50 条回归集对比 precision/recall；先做分环节日志，定位是哪一层漏的。

#### ⑧ 产品 / 商业 / 边界

- “三条都满足但最后没做，为什么？”
- “谁在用？进入人工访谈比例？商业化？”

**答**：三条是必要不充分；还要看团队能不能做、有没有渠道。
现在内部产品/运营在用，每周 20~30 个候选，人工筛完 3~5 个进访谈；
商业化先验证“愿不愿意为省时间付费”，不急着定价。

### 1.3 5 轮主线脚本（推荐路径）

| 轮次 | 面试官大概率问 | 你这样答（要点） |
|---|---|---|
| Q1 | 你负责哪块 / 项目怎么跑 | 30 秒 pitch + “我负责编排/提示词/评测” |
| Q2 | 固定提示词 / 65% 怎么测 | 召回 vs 判定；50 条分层抽检；承认样本小 |
| Q3 | 去重/验证/替代方案 | 两层去重；两个独立来源；检索优先、模型归纳 |
| Q4 | 架构/失败恢复/prompt 迭代 | 串行 + 工具；重试/降级；固定回归集 |
| Q5 | 反问 | “你们更看重召回还是 precision？先优化哪块？” |

### 1.4 框架外速答（被问到就用的短句）

- **为什么不用端到端大模型直接判断？** 成本高、不可追溯；规则召回 + 模型抽取 + 工具验证更稳。
- **和通用搜索/人工分析的区别？** 固定提示词召回 + 多源验证 + 证据链接，能追溯。
- **数据合规？** 只取公开可见内容，限速，不存个人身份信息。
- **如果重做？** 先把“什么算真需求”的评测集和口径做扎实，再扩来源。
- **团队协作？** 每周 bad case 会，产品拍板标准，工程做采集，我负责编排和评测。

## 2. 线 B：大模型算法工程师 × 视频转结构化

### 2.1 30 秒项目介绍

> 我是做大模型算法和多模态内容理解的。最近做的是把网页视频转成结构化文字和表格：
> 输入一个视频链接，输出章节大纲、要点、表格和带时间戳的引用。我负责 pipeline、
> 结构化抽取的 prompt 和评测。

### 2.2 问题地图（实测问法 + 回答要点）

#### ① 个人贡献 / 最大挑战

- “你负责哪一段？整体架构你定的还是只做某一环？”
- “最大挑战是什么？”

**答**：我负责整条 pipeline、结构化抽取 prompt 和评测；模型是现成的多模态模型，
没有从头训练。最大挑战是**上游噪声和表格结构**，不是模型本身。

#### ② 链路 / 章节边界 / 表格来源

- “先抽帧、抽音轨转文字再总结，还是端到端？”
- “章节边界怎么定？幻灯片切换、语音停顿还是模型判断？切错会怎样？”
- “表格是从哪来的？”

**答**：下载切片 → 音轨 ASR → 关键帧 OCR/视觉理解拿 PPT 和表格 → 按章节切块滚动摘要 →
合并全局大纲。章节边界先用幻灯片切换/语音停顿做候选，再让模型校正；切错只影响局部摘要，
不会重跑整条链路。表格来自幻灯片 OCR 的单元格结构。

#### ③ 上游噪声 / 错误率

- “ASR、OCR、视觉理解错误一路传下去，怎么处理？量化过各环节错误率吗？”
- “端到端可用率多少？”

**答**：分环节埋点：ASR 用人工转写算 WER，OCR 抽幻灯片页看字符准确率，视觉只看关键帧分类。
低置信度片段标“不确定”，不让模型硬编；每条要点带时间戳回链，人工可抽查。

#### ④ 长视频 / 分块 / 合并

- “切块粒度怎么定？按固定时长还是内容边界？”
- “分块合并后要点召回比全文高还是低？”
- “前后章节重复/冲突怎么处理？”

**答**：按章节/语义切，不按固定时长；每块只基于本块原文，合并只做去重和归类，不新增事实。
前后重复用相似度去重；冲突保留两条并标“前后不一致”，不擅自选一个。

#### ⑤ 表格 / 忠实度

- “表格‘不改结构’怎么验证？还原准确率多少？”
- “怎么判断填进去的内容没编造？单元格级比对还是只看结构？”
- “原视频没有的数据点，丢弃还是保留？靠人还是自动检测？”

**答**：表格用 OCR 单元格结构约束，模型只填内容；评测做单元格级比对，人工复核比例约 20%。
原视频没有的数据点默认丢弃；自动检测用“每个要点能否在原文找到支持片段”，支持率低就删/标不确定。

#### ⑥ 评测集 / 7% 错误

- “50 个视频怎么选？领域/时长/画质/PPT 覆盖？调参集和测试集怎么分？”
- “换一批视频，7% 还能复现吗？剩下 7% 是什么？”

**答**：50 个按领域、时长、有无 PPT 分层，调参/测试分开；7% 主要是口误/专有名词和跨页表格。
换一批肯定有波动，所以看的是相对降幅和错误类型，不是死守一个数。

#### ⑦ 成本 / 延迟 / 上线边界

- “一小时视频端到端多久？成本主要在哪？”
- “为什么先切 30 分钟？‘稳定’的标准是什么？”

**答**：一小时 3~5 分钟，成本在 ASR 和关键帧 OCR；30 分钟是成本和表格准确率的折中。
“稳定”看三条：表格人工复核错误率、事实错误率、章节切分准确率，达到阈值才放长视频。

#### ⑧ 版权 / 训练数据 / 商业化

- “版权怎么处理？转写文本会不会训练公共模型？”
- “如果内部微调，训练/评估怎么划分？怎么判断学到忠实抽取而不是过拟合？”

**答**：只处理用户有权访问的内容，不公开原视频，不训练公共模型；内部微调按视频/领域划分
训练和评估，指标看单元格级准确率和事实错误率，不看整体 loss。

### 2.3 5 轮主线脚本

| 轮次 | 面试官大概率问 | 你这样答（要点） |
|---|---|---|
| Q1 | 负责哪块 / 链路 | 30 秒 pitch + “我负责 pipeline/prompt/评测” |
| Q2 | 上游噪声 / 错误率 | 分环节埋点；低置信度标不确定；时间戳回链 |
| Q3 | 滚动摘要 / 表格 / 忠实度 | 按章节切；只基于原文；单元格级比对 + 支持片段 |
| Q4 | 50 个视频 / 7% / 评测 | 分层抽样；调参/测试分开；7% 是口误/术语/跨页表格 |
| Q5 | 反问 | “团队更关注成本还是准确率？先优化哪边？” |

### 2.4 框架外速答

- **为什么不做端到端多模态大模型？** 长视频成本/上下文不可控；分步可评测、可回退。
- **为什么用现成模型不自己训？** 数据量和迭代速度不划算；价值在 pipeline 和评测。
- **如果重做？** 先做表格/术语的结构化和评测集，不先追全自动。
- **商业化？** 按小时/视频收费，先验证内容团队愿不愿为省时间付费。
- **合规？** 只处理有权内容，不公开原视频，不训练公共模型。

## 3. 数字口径卡（按实际改）

| 线 | 数字 | 被追问时怎么说 |
|---|---|---|
| A | 5 个来源、1 万条/天 | 公开可见内容，限速；不是全量 |
| A | 800 条信号 → 200 条去重 → 50 条抽检 | 分层抽样；只代表方向 |
| A | precision 65% | 50 条样本，置信区间宽；下一步扩到 100~200 |
| A | 每周 20~30 候选 → 3~5 进访谈 | 三条标准是必要不充分 |
| B | 50 个视频 | 按领域/时长/PPT 分层；调参/测试分开 |
| B | 覆盖率 85%、事实错误 7%、时间戳 90% | 人工标注；7% 主要是口误/术语/跨页表格 |
| B | 1 小时视频 3~5 分钟 | 成本在 ASR + 关键帧 OCR |

> 万能句：**“这个数是在 X 条样本上测的，只能看方向；我们下一步会扩到 Y 条并看 Z 指标。”**

## 4. 演示动线

1. 待机页：K3 选岗位 → 左上角「− 轮数：10 +」选 5 → K2 选标准；
2. K1 说 30 秒自我介绍；
3. 按 Q1~Q5 回答（每次 K1 一轮），第 6 次回答后出报告；
4. 网页看报告：总分、四维、逐题复盘、表达状态；
5. 想展示多岗位：报告后按 K3 换另一个岗位，再来一场。

## 5. 反问清单（选一个问）

- “你们现在更看重召回还是 precision？如果只能先优化一个，会先动哪块？”
- “团队现在更关注成本，还是准确率？”
- “这个岗位前三个月，最希望我先把哪块接起来？”
