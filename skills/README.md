## 一、概述

本目录包含 AI 模拟面试官的 **5 个核心 Skills**，每个 Skill 对应面试流程中的一个环节。Skills 以 JSON 格式定义 Prompt 模板，由 `cloud/llm_service.py` 加载并调用小米 MIMO LLM API 执行。

### 1. `start_interview` — 开始面试

**输出**：

```json
}
```

### 2. `next_question` — 下一个问题

**功能**：根据用户回答判断是追问还是提出新问题

**输入参数**：
- `role`：面试岗位
- `history`：完整对话历史
- `last_answer`：用户的最新回答

**输出**：
```json
{
  "text": "下一个面试问题或追问",
  "next_action": "continue"
}
```

**实现状态**：✅ 已完成（2026-09-18 重写，见台账 §11.21）

**待优化项**：
- [x] ~~收集真实面试对话数据~~ —— 已接入 `../question_bank/`（2830 题）
- [x] ~~优化追问逻辑~~ —— 已加入【面试纪律】段，取自同作者开源项目 myagent 的
      mock-interviewer 方法论。**9/18 晚按 A/B 结果降级**：原 7 条 → 保留 3 条
      （不给反馈 / 同一话题最多追 2 轮 / 模糊词追一层），"一次只问一个问题"由
      【硬性要求】第 3 条兜住。降级依据见台账 §11.21
- [ ] 测试不同岗位的追问质量

**提示词结构（2026-09-18 起，顺序不能调）**：

```
你是{role}岗位的面试官…
【面试纪律】3 条        ← 方法论（不给反馈 / 追 2 轮上限 / 模糊词追一层），用 · 不用编号
{reference_block}      ← 题库参考题，由 cloud/question_bank.py 生成，可能为空串
【硬性要求】1~5 + 正确示例    ← 必须留在**最后**；别再加"错误示例"（见约束 3）
```

三条约束，动之前先读台账 §11.20 / §11.21：

1. **【硬性要求】必须留在结尾**。§11.20「话痨」的修复靠的就是结尾这几条的 recency；
   参考块若排在它后面，等于把「120 字以内」推远，话痨会复发。
2. **参考块只进 system prompt，绝不进 history**。history 里出现参考题就是给模型
   递了它自己的范例 —— 那正是「模型抄自己」的燃料，会自我强化、越写越长的原因。
3. **提示词里不要写「错误示例」** —— 这条是本文件踩过坑才加的，别再把它们加回来。
   9/18 的 A/B 实测：原来结尾有一句 `错误示例：**判断：需要追问** 理由：候选人回答过于简略……`，
   在被污染的会话历史下，模型把这句话**几乎逐字抄了回来**（输出 `判断：追问细节 … 理由：
   候选人的回答过于简略…`，216~229 字），TTS 会一字不落地念出来。
   对模型来说，**"反例"首先是一段可模仿的文本**，而它又排在提示词最后（recency 最高）。
   要禁止什么，在【硬性要求】里写清楚就够了：`不要任何分析、判断、理由、说明、备注、标题、分点或表格`。
   ⚠️ **但别指望删掉它就能解决**：删掉后同一批输入重测，30 次里仍有 **4 次**输出
   `判断：追问细节 … 理由：…`（169~229 字）—— 模型改从**历史里**学那个格式了。
   真正拦住它的是代码里的闸门 [`cloud/reply_guard.py`](../cloud/reply_guard.py)：
   出口剥一遍、读进来的历史也剥一遍。**把闸门关掉再量，同一条被污染历史 10 次里
   仍有 5 次是元叙述**（169~237 字）—— 上线形态下 A/B 的 30 次 0 残留，
   是闸门救回来的，不是模型学乖了。详见台账 §11.21。
   **结论：提示词只能"劝"，拦不住的要在代码里拦。**

> 岗位映射不到题库时 `{reference_block}` 为空，提示词退化成没有题库的样子（自由提问），
> 不会报错。演示岗位 `AI 应用开发` 在题库里，正常有块。

### 3. `evaluate_answer` — 评估回答

**功能**：对用户的单个回答进行打分和点评

**输入参数**：
- `role`：面试岗位
- `question`：面试问题
- `answer`：用户回答

**输出**：
```json
{
  "text": "打分和点评",
  "score": 8,
  "dimensions": {
    "logic": 8,
    "professionalism": 7,
    "clarity": 9
  }
}
```

**评分维度**：
- `logic`（逻辑性）：回答是否有条理、逻辑清晰
- `professionalism`（专业性）：是否体现专业知识和经验
- `clarity`（表达清晰度）：表达是否简洁明了

**实现状态**：⏳ 代码已实现，待数据优化

**待优化项**：

### 4. `generate_feedback` — 生成报告

**功能**：面试结束时生成完整的评估报告

**输入参数**：
- `role`：面试岗位
- `history`：完整对话历史

**输出**：
```json
{
  "text": "结构化面试评估报告",
  "next_action": "finish"
}
```

**报告结构（2026-09-18 重写为固定 6 句）**：
1. 总评（一句话结论）
2. 逻辑性 —— 有据可依时引「」原话
3. 专业度
4. 表达清晰度
5. 岗位匹配度
6. 一条最具体的改进建议

**实现状态**：✅ 已完成（2026-09-18 重写，见台账 §11.21）

**待优化项**：
- [x] ~~收集优秀面试评估报告样本~~ —— 结构与「四维度」取自 myagent 的
      mock-interviewer 方法论，非自创
- [x] ~~优化报告格式和内容结构~~ —— 改成固定 6 句，去掉 Markdown 小标题和编号列表
- [x] ~~添加岗位针对性的评估标准~~ —— 第 5 句即岗位匹配度

**为什么改成"固定 6 句 + 上限 250 字"**：报告是要**读出来**（TTS）的，不是给人看的
文档。原来的「1. 2. 3. 4.」编号一进语音就变成"一、二、三、四"啰嗦一串，且模型倾向
越写越长——实测有的轮次冲到 400+ 字，合成音频撑到 3 MB 以上，逼近端侧 8 MiB
响应上限（`CLOUD_RESP_MAX`）。句子边界比 Markdown 结构更适合语音。

**两条要求**：

1. **必须含「」原话引用**（≤12 字，抄候选人自己说过的话）。这是让评委听出
   "它真的在听我说话"的关键；没有引用的报告和通用模板没有区别。
2. **没提到的维度写「未涉及」**，不许编。宁愿短，不许无中生有。

**实测**：11 轮试运行（`cloud/rehearsal.py`）中报告轮 100% ≤250 字、100% 含「」
引用、零 Markdown 残留。

## 四、技术实现

### 4.1 调用链路

```
用户语音 → ASR → 文字 → Skill 函数 → LLM API → 回答文字 → TTS → 语音播放
```

### 4.2 代码位置

- **Skill 模板**：`skills/*.json`（本目录）
- **Skill 实现**：`cloud/llm_service.py`
- **LLM API**：小米 MIMO API（`mimo-v2.5` 模型）

### 4.3 调用示例

```python
from llm_service import start_interview, next_question, evaluate_answer

# 开始面试
result = start_interview("AI 应用开发")
print(result["text"])  # 输出第一个问题

# 生成下一个问题
history = [
    {"role": "assistant", "content": "请介绍一下你自己"},
    {"role": "user", "content": "我是..."}
]
result = next_question("AI 应用开发", history, "我是...")
print(result["text"])  # 输出下一个问题或追问

# 评估回答
result = evaluate_answer("AI 应用开发", "请介绍一下你自己", "我是...")
print(result["text"])  # 输出评分和点评
```
